# Emulos360 0.6.0

Paquetes Windows x64 y Linux x86_64 preparados para revisión del propietario.
La publicación, commit y push siguen a cargo del usuario. Esta entrega conserva
un único core Canary Netplay y los cambios locales del mando existentes.

## Cambios seleccionados del core

La base permanece en `6dbaa1fefd1e07cc3d5377e763c68fe8073cbe8c`, sin actualizar
la rama completa. Se incorpora una serie reproducible:
`0001-emulos360.patch` conserva las extensiones propias y
`0002-core-maintenance-0.6.0.patch` contiene las siguientes correcciones y tests.

| CPU/HIR | Extracción constante de bytes/shorts en el elemento correcto y máscara de índice de 16 bytes | Canary `5ce7c336df060d043b0a2351889ec8789322d035` |

Adaptaciones locales adicionales: el assert de carga de fd_set admite el máximo
que su validador ya permite; el QoS ignora payloads que no caben en su longitud
uint16 en vez de reducir silenciosamente su tamaño; comparación del handle
inválido expresada con su tipo. No se cambia el payload normal ni se habilitan
stubs HTTP o ajustes gráficos globales.

Las atribuciones originales permanecen en los parches individuales de
`patches/xenia-upstream-candidates/`; el agregado contiene los diffs de las
fuentes y tests reales. La preparación comprueba ambos parches antes de aplicar
y es idempotente en Windows/Linux.

## Validación y límites

Los contratos de red se prueban con fragmentos copiados byte a byte de la
fuente de producción, wrappers big endian reales y fixtures de asignación,
object table y UPnP: 204 assertions Windows/Linux aprobados. No es la ejecución
completa de exports ni una sesión online real. Linux ASan/UBSan ya pasa sin
informes para casos nulos, capacidad máxima/excesiva, handle inválido, UPnP
activo/inactivo/ausente, datos QoS 0/1/17/65535/65536/65537 y reserva fallida.

La verificación final queda en [0.6.0-validation.json](0.6.0-validation.json): compilaciones,
tests CPU/JIT, base/hilos/UTF-8, sanitizers, interfaz, actualizador, arranque y
paquetes. No se afirma aumento de FPS ni corrección de las caras negras de
Gears. Validar títulos, imagen y Netplay con la misma versión/TU/configuración
sigue siendo una comprobación del propietario antes de aceptar esta entrega
como estable. No existe garantía absoluta de ausencia de regresiones.

No se incorporan cambios amplios de posiciones MSAA/Gears, polling/futex,
viewport negativo, tolerancia de fetchs, propiedades/perfiles, objetos Kinect,
stubs XHTTP ni la reescritura UPnP. Conservan los límites del dossier y siguen
pendientes cuando necesitan una reproducción o revisión más amplia.

La instalación usada para jugar y sus datos no se sustituyen durante la
preparación. Los ZIP/TAR excluyen perfiles, partidas, ajustes y datos del
servidor. Los scripts del actualizador corregidos se mantienen.

## Publicación para que el actualizador la detecte

Publicar una release normal con tag **v0.6.0**, sin marcarla como borrador o
pre-release, y adjuntar estos nombres exactos y sus SHA-256:

- `Emulos360-v0.6.0-windows-x64.zip`
- `Emulos360-v0.6.0-linux-x86_64.tar.gz`

La versión integrada de la interfaz es 0.6.0. El actualizador consulta
`releases/latest`, compara versión y verifica nombre, tamaño y digest del asset.
Preparar archivos locales no publica una release ni permite detectarla aún.

Resultados finales: ambos cores enlazan; CPU Windows 247/1077 y Linux 247/1075,
hilos 7/108, eventos 3/25 y UTF-8 13/466 en ambos. Interfaces 5/5 por sistema;
contratos de red 204 assertions por sistema; ASan/UBSan Linux para red y
4199424 extracciones CPU. Perfiles y almacenamiento reales pasan con datos
sintéticos en Windows/Linux. El backend Node/MongoDB empaquetado pasa 4/4 por
sistema con una base temporal; esto no es una partida Netplay entre equipos.

El check del catálogo verifica 282 opciones públicas y dos flags internos de
avatares que PlayerServices ya administraba, sin exponerlos ni modificar sus
valores. Los scripts de puente aceptan EMULOS_CORE_TEST_BINARY para repetir las
mismas pruebas con el core Linux. Se auditaron 2033 archivos del snapshot
Windows contra las fuentes actuales, exceptuando bytecode de shaders regenerado.
Los hashes de los runtimes dentro de los archivos coinciden con los binarios
verificados; ZIP/TAR sin datos personales ni cores retirados, con permisos y
ELF x86_64 Linux comprobados. Los SHA-256 acompañan ambos archivos.
